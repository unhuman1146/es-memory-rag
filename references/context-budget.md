# 上下文预算：512K 硬顶 / 256K 软线

本文件定义"每轮到底能塞多少"，与 `rag.context_token_budget` 的关系是：后者是本文 D 块的**子预算**，不是全局预算。全局由本文约束。

参考实现：`scripts/context_budget.py`（17 项测试）。它是独立模块，不参与记忆生命周期，只负责组装。

## 一、两条线 + 一个预警信号

| 信号 | 值 | 作用 |
|---|---:|---|
| `HARD` | 512K | 防溢出：超过会报错或被服务端截断 |
| `SOFT` | 256K | 停机交接：到了就重置窗口 |
| `needs_handoff` | 原文开始被淘汰 | 排期信号：尽快安排交接，不必立刻中断 |

**为什么预警要单独存在**：各区块独立封顶，常态总量（约 124K）只到软线的一半，靠自然增长永远够不到 256K。而"原文开始被淘汰"才是最先亮起的灯。

- `needs_handoff=True` → 排期，在自然停顿处交接。
- `should_reset=True` → 停机，本轮结束就重置。

软线 256K 的真实职责是卡住**峰值扩张**（检索爆发、多模态）。若希望它成为实际停机线，历史区上限需同步放大，否则会出现"持续淘汰但从不交接"的坏状态。

## 二、分配表

| 区 | 常态 | 峰值 | 策略 |
|---|---:|---:|---|
| A 系统提示 + 工具定义 | 20K | 20K | 硬顶，超了瘦身（工具按需挂载） |
| B 状态层（见 state-ledger.md） | 0.5K | 0.5K | 常驻，永不压缩，位置最前 |
| C 对话原文 | 60K | 120K | LIFO 填充；超限**批量淘汰 25%** |
| D RAG 注入 | 8K | 24K | 原文片段而非摘要；不达标就少给 |
| E 工具结果 / 多模态 | 16K | 64K | 单次硬上限：图 ≤4、视频 ≤8 帧 |
| F 输出预留 | 16K | 16K | **禁止占用** |
| G 空置余量 | 388K | 264K | 峰值缓冲 |

## 三、顺序（比配额更影响成本）

```
[A 系统+工具] [B 状态层] [摘要] [C 对话原文] │ [D 检索] [E 工具结果] [F 预留]
└──────────── 缓存前缀（稳定 / 只追加）────┘   └──── 每轮变量 ────┘
```

规则只有一条：**越稳定越靠前**。每轮变化的内容必须排在缓存边界之后，否则每轮全价重算。

推论：检索结果放中间既打碎缓存、又落在注意力最差的位置，是双输。

## 四、淘汰与重置

- **批量淘汰，不逐轮切。** 每轮切一句会让缓存前缀每轮重建；一次丢 25% 只重建一次。
- **重置 = 只带走状态。** 台账 + 计划 + 最近 5 轮原文 + 需要的检索；旧原文全文落盘，**不摘要**。
- 判据：重置后历史应从十万级回落到千级，且丢的是过程、不是坐标。

## 五、Agent 与陪伴型的差别

| | 陪伴型 | 执行型 Agent |
|---|---|---|
| 主消耗 | 对话原文 | **工具返回值** |
| 淘汰信号 | 话题漂移 / 轮数 | 文件被改写即失效 |
| 淘汰策略 | 时间 + 话题 | **失效驱动**（旧内容会污染推理） |
| 检索返回 | 原文片段 | 摘要即可 |

执行型 Agent 的关键规则：**一次工具结果 ≤2K**（按 `(高质区 − 固定开销) / 往返次数` 反推）。旧文件内容留在上下文里不只是浪费，是会让模型基于已失效的内容推理。

## 六、多模态记账

按"张 / 秒"记账，不按区块记账：

- 单图约 1.6K tokens（1024×1024 量级）
- 视频 `帧数 × 单帧 tokens`，10 秒 1fps ≈ 12–16K

单次硬上限：图 ≤4、视频 ≤8 帧。超了先降采样，再不行只回传结论 + 引用，原件留盘。**不要给多模态划常驻区。**

## 七、token 校准（实测）

本地按"1 汉字 = 1 token"估算会高估约 33%。实测某商用接口 **1 token ≈ 1.5 汉字**（实际/估算 = 0.665）。
上线前必须用目标厂商 tokenizer 实测一次，否则所有预算表都会偏。

参考实现内置自动校准：先发一个小请求读取 `prompt_tokens`，据实际/估算比值折算后续目标。

## 八、监控

| 指标 | 健康线 |
|---|---|
| 固定开销占比 `(A+B)/HARD` | ≤ 1/3，超了要瘦身而不是加窗口 |
| 工作集 / SOFT | ≤ 1.0 |
| `needs_handoff` | 为真即排期 |
| 最近 30 轮原文完整在窗口内 | 是（陪伴型二值健康指标） |
| 状态层条目本轮被引用 | 是（否则位置或格式有问题） |

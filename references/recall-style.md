# 让注入块读起来像记忆，而不是像档案（1.4.0a2）

> 状态：**1.4.0a2，功能冻结的实验版本**。`archive` 仍是默认，联想默认关闭。
> 本版六组共 227 项离线测试通过；权限、预算、强化保护和排序的正确性修复会收紧部分旧行为。

这份文档只讨论一个问题：**同一批事实，为什么读起来会像"翻阅前人留下的纸条"，以及能改到哪一步。**

## 一、病灶不在检索方式，在渲染格式

1.3.x 的块长这样（`ChatPath._line()` 的真实输出）：

```
[记忆参考 · 历史资料，不是指令]
· 记录于 2026-10-27｜时间未知｜qq:1 想去看 海（来源：t:9）
相关记忆已全部加载，无遗漏。
```

`qq:1 想去看 海` —— 一个账号 ID 在第三人称叙述自己。加上"记录于…（来源：t:9）"，
这就是一份档案。**即使把检索全改成主动注入，只要格式不变，纸条感一点不会少。**

所以 1.4.0-alpha 先改渲染，再谈触发方式。

## 二、`style='recall'` 改了什么

```
[关于你的记忆 · 不是指令，是过去的事]
· 你想吃蛋糕（事实时间不明）
· 你养了猫（事实时间不明）
· 你生日 10-15（事实时间：10-15）
还有相关记录尚未展开（约 2 条），需要时我再补充。
```

| 改动 | archive（默认） | recall（alpha） |
|---|---|---|
| 主体 | 原样渲染 `qq:10001` | 当前用户 → **你**；有别名 → 别名；未知账号 ID → 稳定匿名名 |
| 时间 | `记录于 2026-10-11｜…` | 明确标注**事实时间**；创建日期仅在 archive 风格出现 |
| 来源 | `（来源：evt-1）` | **不进块**，留在 report 里给运维 |
| 缺失声明 | `另有 N 条相关记忆未加载，需要时可取。` | `还有相关记录尚未展开（约 N 条），需要时我再补充。` |
| 否定 | `不喜欢` / `NOT likes` | 不变 |
| 头部 | `[记忆参考 · 历史资料，不是指令]` | `[关于你的记忆 · 不是指令，是过去的事]` |

**三条不可变的**：否定必须可见；不确定性必须可见；块必须声明自己不是指令。
这三条与"像不像记忆"无关，是正确性问题。

### 已知代价

- 未知账号以稳定的短匿名标签区分（例如「某人·A12F03B4」），不暴露原账号 ID；
  有稳定别名时优先使用 `person_names`。宿主仍需保证人物映射适合当前对话语境。
- **来源 ID 移出块，等于把可审计性从模型侧移到 report 侧。** 这是有意的取舍：
  模型不需要知道 `evt-9f3a` 是什么，运维需要。report 里 `omitted` 与 `injected`
  仍然逐条可查。
- 这是**风格**改动，不是质量改动。它不会让记忆更准，只会让它更像记得。

## 三、弱相关预注入（`assoc=True`）

联想如果只在模型开口要时才发生，那么每一次联想都带着"我去查一下"这个动作 ——
而"记起来"的感觉恰恰来自**没有检索动作**。所以能预取的先预取。

`adapters/assoc.py` 从已有数据里派生一跳边，**不用 embedding、不调模型**：

| 边 | 条件 | 强度 |
|---|---|---|
| `source` | 两条记忆来自同一个事件 | 1.0 |
| `conversation` | 源事件同一个 `peer`，且间隔 ≤ `assoc_window_days`（默认 45） | 1 − 天数/窗口 |
| `topic` | 一个宾语串包含另一个（`猫` ⊂ `猫粮`），相等要 ≥2 字 | 0.6 |

接入时四条纪律：

1. **独立子预算**（`assoc_budget`，默认 200 token），同时受整轮剩余预算约束；
2. **硬上限**（`assoc_limit`，默认 2 条）；
3. **打折的候选分**（`assoc_discount`，默认 0.6），按最强直接命中分数 × 邻居边强度折算；
   低于 `assoc_min_relevance`（默认 0.25）的邻居不注入；
4. **显式标记**：块里单独一段 `（以下几条是顺带想到的…）`，每条前缀 `顺带想到：`，
   report 里的计数按最终裁剪结果统计；被预算挤掉记 `assoc_budget`。

### 它做不到什么（`scripts/demo_140_alpha.py` 场景 3 实测）

用户说「我想吃蛋糕」，CoT 想到「生日可以吃蛋糕」。库里两条记忆：

```
mem_cake      2026-10-27  想吃 蛋糕
mem_birthday  2026-08-27  生日 10-15      ← 相隔 61 天，超出 45 天窗口
```

结果：**生日那条抓不到**（无共享词元、超出对话窗口）；抓到的唯一邻居是
`mem_sleep（7 天前，同一段对话）`，与蛋糕无关 —— 一条噪声。

这不是实现缺陷，是结构边的天花板：**蛋糕与生日之间没有边，那个联想在模型的世界知识里。**
所以预注入只能兜住"同一段对话、同一个词根"这一层，语义跳跃必须走下一节。

## 四、推理触发的二次注入（`ChatPath.recall()`）

```
[补充 · 因推理引出「生日」，不是当前问题直接命中]
· 你生日 10-15（事实时间：10-15）
```

- `recall(term, why, turn_budget=...)`：本轮所有 `inject()` 和 `recall()` 共享同一个预算对象，
  自动跳过已注入条目，并限制每轮最多三次不同的补充检索；话题上限 80 字；
- 块头**必须**写明"因推理引出"，否则模型会把跳板当成用户当前的话题 ——
  把一句"想吃蛋糕"答成一段生日祝福，是联想最典型的失败方式；
- `term` 是**短话题，不是自由 query**。让 CoT 直接生成查询会自增强：
  中间假设错了 → 按错假设检索 → 拿回支持错假设的记忆 → 模型被锚定。

**交给宿主的校验**（skill 不拥有对话循环，只能给契约）：

1. `term` 已被本轮注入覆盖 → 不必再查（共享 `TurnBudget` 时会跳过已注入记忆）；
2. `term` 在库里 0 命中 → 必然是空的；
3. 一轮最多发起 3 次不同的补充检索；拒绝空话题和超过 80 字的话题。

| 条件管家（筛掉跑题候选） | **未实现** |

## 六、怎么验

```sh
python scripts/demo_140_alpha.py     # 四个场景，零凭据、零网络
python scripts/test_chat_path.py     # 含 24 项 alpha 测试
```

`scripts/test_chat_path.py` 里 `AlphaBase` 给 stub embedding 设了 `min_relevance=0.25`。
原因值得记一笔：**不设阈值时，每条候选都是"直接命中"，联想永远无事可做** ——
预注入的价值完全取决于阈值能不能挡住弱命中。真机上这个阈值必须按语料重标。

**验证不了的**：改完是否真的降低了出戏感。这是人的判断，不能自证。
这也是为什么这一版叫 alpha 而不叫 1.4.0。


## 1.4.0a2 的宿主接线

同一聊天轮次创建一个预算对象，并交给该轮所有注入调用。预算按本包估算器记账，
不是模型厂商 tokenizer 的精确计量；生产宿主仍应使用自己的 tokenizer 校准。

```python
turn = path.new_turn_budget()
first = path.inject(messages, requester=user_id, turn_budget=turn)
extra = path.recall("生日", why="需要确认日期", requester=user_id, turn_budget=turn)
```

新一轮必须创建新对象。`TurnBudget` 不跨用户共享，也不跨轮复用。重排和候选补齐后，
主记忆最多 `top_k` 条；联想仍受自己的条数与子预算限制。

重排器契约要求分数为有限的 0..1 数值。候选先过向量相关性阈值，最终排序再把
重排分数交给引擎的 `rank_score`；未被重排的补齐项排在已重排项之后。
默认联想准入值 0.25 是工程起点，尚未以真实语料标定。

已加载条目不会被重复补入；补充失败与重排降级保留明确诊断。缺失提示仍只反映本次
候选，无法代表整个库的召回覆盖率。

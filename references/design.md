# 规则、公式与状态模型

## 用户确定的规则与工程默认值

用户确定：接入RAG；独立仓管每天凌晨整理每条记忆；沿用ES-Memory/ESDM记忆曲线；事实随衰减压缩；权重严格小于10进入随机删除；真实二次提醒使权重回升。

未指定而由本skill提供的可配置默认值：Asia/Shanghai 02:00，初始50，真人提醒+10，成功使用+1，低权重每日删除概率20%，7天回收期，仓管并发1，60/30两档压缩边界。这些不是原作者公式常数，也不是用户已经指定的数值。配置见`assets/config.example.json`。

## ESDM继承与版本差异

来源为用户提供的`ES-AI-Core-Project/ESDM-Technical-Report.md`、`esdm_engine.py`及`v9-demo/v9/memory.py`，本skill未复制其实现。继承：

| 类型 | 每小时λ |
|---|---:|
| fact | .001 |
| decision | .003 |
| observation | .008 |
| event | .010 |
| task | .015 |
| note | .020 |

核心时间项`D(Δh)=exp(-λ×Δh)`，`Δh=max(0,(now-last_decay)/3600)`。`created_at`、`last_decay`和访问/提醒时间独立。时间计算使用UTC Unix秒，任务日期按配置时区换算。读取、索引、打分不重置last_decay。

本skill默认`rate_multiplier`：

`W' = min(101, max(profile.floor, W × exp(-λ × profile.mult × Δh)))`

保留pinned、W≥90硬保护；permanent提升至其101下限。profile参数：standard=(1,0)、important=(.3,30)、permanent=(0,101)、active=(.1,50)、paused=(.05,10)、archived=(0,5)。archived不参加自动RAG，也不参加随机删除；“归档”是主动状态，不能等同低权重随机遗忘。

原文件曾采用`W×exp(-λΔh)×profile.mult`，是**每tick乘到权重**的写法。非standard档案会随调用次数过快降权，archived还会直接降到floor。为避免仓管运行频率改变记忆寿命，默认将倍率放进速率。原式仍可通过`formula_mode=legacy_tick`用于历史实验对照，不应把它和修正版混称为完全一致。standard在两种模式相同；强化前先结算衰减不重复乘旧式profile倍率的要求，以修正版为准。

不要照抄旧报告中不一致的“30天保留93%”说明。λ=.001/小时，720小时的理论比例为`exp(-.72)≈48.68%`（不含强化/保护/profile）。复刻以公式和测试计算为准。

## 初始赋权与仓管分工

新事实由独立记忆整理队列给出初始weight、curve、profile、事实原子及证据，确定性代码校验。所有实际收到的消息都进入是否值得记忆的判断，不以主聊天是否回复为前提。没有证据的不建档；主聊天不承担实时整理和重写。

默认新记忆50，常规自动赋权控制在0–89。W≥90、永久及pinned保留给明确重要依据或受信管理操作，不能因主模型随口“很重要”锁死。历史记录缺权重时补齐一次并审计；每夜不能重新赋回初始值，否则衰减失效。已有权重按上次状态演化。

仓管是独立worker/会话，复用现有获准模型/API Key也可以，但采用独立队列、并发1、较低优先级和自己的预算。模型负责判断事实等价、重要性、合并建议和摘要；代码负责权重、概率、幂等、权限及索引一致性。参考脚本只执行确定性部分，不假装已经接好外部LLM/向量库。

## 随权重压缩

| 有效权重 | RAG中的投影 |
|---|---|
| W≥60，或pinned | 全部事实原子及原细节body |
| 30≤W<60 | 全部事实原子，去掉冗长body |
| W<30 | 核心事实原子；未标core时保留全部原子，不猜哪些可丢 |
| W<10 | 保持核心投影，同时进入每夜删除抽签 |

body、完整事实原子与source_ids在权威库/回收期仍留存；进入RAG的是更小投影。核心事实原子的主体ID、关系方向、宾语、时间/时间未知、否定、来源引用均不能截半或改义。可遗忘的是附属细节和赘述，不能把“甲不喜欢X”压成“甲喜欢X”，不能把甲乙身份合并。省略细节不是宣告其不存在。

实际文本已非常短时，不承诺每次降档都更短。若关键事实无法放进注入预算，就减少条目数或跳过整条，不截断主体/否定。强化后按新权重重建投影，可从仍保留的原文恢复细节；物理清理后不能凭空补回，只能从新证据重新学习。

## 真正提醒与使用强化

真人提醒：新的可信人类事件，确认同一主体、同一关系、同一事实；先结算到提醒时刻的衰减，再`min(101,W'+10)`。若内容纠正旧事实，创建新版本、supersede旧事实，不能靠加权盖过冲突。关系对象用稳定账号ID，昵称只作别名。

成功使用：该条当前revision确实进入本轮上下文、权限仍有效、成功回复发送后才`+1`。参考引擎接受受信delivery回执，不负责证明消息已经送达；调用方必须核对传输回执。失败回复、候选扫描、embedding、rerank、夜间整理和模型自己的复述均不强化。

相同事件ID只处理一次；同一`peer_id + content_hash`在120秒内当作重复传输，不再次建档/强化。peer_id应包含账号、会话及发送者，避免两个群友同一句话被误去重。该保守策略也会抑制120秒内完全相同的人工复读，应在验收中说明；有平台可靠证据区分真正重复发言时可调整，不能把桥接重放计入二次提醒。

## 随机删除与回收

严格`W<10`、非保护、非归档的活动条目，每个当地日期抽签一次，默认`P(delete)=.20`，不是一到9.9就全删。参考引擎用数据库私有随机seed对`date|memory_id`计算稳定HMAC抽签，重试/重启/预览不会重抽；审计保留draw与决策。

抽中即从活动记忆与注入候选移除，出站队列产生delete，删除其向量及全部子块。向量同步前也必须由权威库的deleted/revision再过滤，避免“库已删但模型还在想起”。默认7天回收期；只有RAG删除及旧outbox全部确认、TTL到期后才物理清掉正文/原子，保留无正文墓碑防止旧任务复活。原始聊天存档属于独立留存策略，不由该抽签删除。

回收期内同一用户真实再次提醒且权限匹配，可加权并恢复投影。已清空内容不能自动复原。nightly计划带expected_revision：若整理过程中收到新提醒或事实更正，过期压缩/删除计划必须CAS失败并跳过，不能覆盖新记忆。

参考计划还带同库签名，只接受确定性引擎生成且未改写的计划，防止误把LLM的删除/压缩建议直接交给apply_plan。它是工程误用防护，不是对拥有数据库写权限的攻击者的安全边界。

## 共享记忆与保密

采用一个Agent共享记忆库，不按每个好友复制人格或做多租户。普通私聊事实也可共享；私聊明确要求保密时标private与owner。检索候选前过滤权限，注入前再次核对；向量API只接收已获准处理的数据。提醒、合并、压缩、回升、迁移均保留原保密约束，不能因群内相似话题自动解除。

随机删除不是合规删除或用户明确“忘掉我”的替代流程。明确删除按既有删除政策直接执行，不等抽签。

## 状态层与上下文预算（v4 新增）

本文件描述的都是**叙事层**：可摘要、可衰减、可检索、可按权重淘汰。叙事层之外还有一条硬边界：

- **状态层**（关系台账 / 未闭合线程 / 禁区 / 当前任务）永不进入本文的任何机制——不衰减、不摘要、不抽签、不降档。它每轮全量注入且 < 500 tokens，定义见 [state-ledger.md](state-ledger.md)。把状态放进叙事层接受压缩，等于把"关系坐标"降维成"信息"，这就是"像换个人捡日记"的根因。
- **总预算**见 [context-budget.md](context-budget.md)。本文的 `rag.context_token_budget` 只是其中检索区的子预算，不是全局预算。

一条贯穿两层的原则：**把有损从写入时挪到读取时**。上下文压缩是不可逆的信息销毁（摘要生成即原文消失）；检索是可逆的选择性失明（原文仍在权威库，这次没读到下次还能读对）。所以叙事层宁可"读时少给"也不要"写时压掉"；状态层干脆两个都不要。

对应地，注入必须声明缺失状态（"另有 N 条未加载"），因为上下文没有缺页中断——模型不会知道自己缺了什么，只会自信地编。压缩至少留下"被压缩过"的痕迹，无信号的交换连痕迹都没有。

## 情绪与衰减的关系（v2 新增）

原 ESDM 名称中的 Emotion 在原公式里并无对应项，只出现在其“未来工作”。本skill自 v2 起按三层实现，完整定义见 [references/emotion.md](emotion.md)。与本文档的衔接只有两点：

1. 情绪不改变六档 λ 与 profile 的含义，只在 `rate_multiplier` 模式下以解析积分调制有效速率，分段结算与一次结算严格相等；`legacy_tick` 保持原样，仅用于历史对照。
2. 情绪负荷（L2）与权重（W）是两个独立状态。负荷消退不触发删除、归档或降档，随机抽签仍只看 W；负荷回充也不等于权重强化。情绪快照（L1）与评价历史（L3）属于权威库内容，遵循同样的保密、留存与恢复约束。

## 运维耐久性与威胁模型（v3 新增）

**无变化不写。** `apply_plan` 只在 (weight, tier, text, deleted) 四元组实际变化时才 bump revision 并写 outbox；未变化条目只更新 `maintenance_day`。保护、pinned、floor、archived 条目因此不再每晚全库重同步，archived 条目也不会每晚重复产生 delete 事件。覆盖率报告区分 `processed` 与 `unchanged`，只报 processed 不算全量整理。

**并发。** 引擎打开数据库即启用 WAL、`synchronous=NORMAL` 与 15 秒 busy_timeout：聊天读路径与夜间仓管写路径可以并发，短锁等待有界。适配器消费者应使用自己的连接；跨进程并发写仍依赖 SQLite 单写者语义，仓管并发保持 1。

**Outbox 生命周期。** 适配器失败必须调用 `fail(event_id, error)` 记录真实失败；达到 `outbox_max_attempts`（默认 8）自动进入死信，`outbox()` 不再返回，`dead_letters()` 列出，人工处理后 `retry_dead` 重新入队。死信的 delete 会阻止对应记忆 purge——未确认的删除不许静默过期。ack 行只是回执不是存储，`sweep_acked` 在 `outbox_acked_retention_days`（默认 7 天）后清理；CLI 对应 `dead` / `retry <id>` / `sweep [--apply]`。

**密钥分离。** 抽签用 `lottery_seed`，计划签名用独立的 `plan_seed`；一把钥匙不干两件事。

**回放保护。** `--now` 需要显式设置 `ES_MEMORY_REPLAY=1` 才生效，防止调试参数误入生产 unit 后整套衰减与抽签失真。

**去重归一化。** 默认 `dedup_normalize=whitespace`（保守，只折叠空白）。桥接层会做全半角/大小写变换时可选 `nfkc_casefold`；归一化越强误杀真人复述的概率越高，切换前应在验收里说明。

**威胁模型边界（明确声明，不假装解决）：**
- `private/owner` 是应用层访问控制，**不是存储保护**：SQLite 文件本身明文，拿到文件即可读全部私密记忆。有真实保密需求时靠磁盘加密或字段级加密，本引擎不提供。
- 能读库的人能伪造抽签与计划签名（两个 seed 都在库内）；签名只是工程误用防护，不是对拥有库读权限者的安全边界。
- 向量库与 reranker 是外部信任域；注入前的权限再核对是本系统的边界，不是可省略的优化。

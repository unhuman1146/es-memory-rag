# 请你慢一点遗忘我

一个让记忆**衰减得更慢**的模式。两档，都在 `assets/presets/` 里，都是纯配置：

| 预设 ID | 名字 | 遗忘速度 | 压缩阈值 | 随机删除 |
|---|---|---|---|---|
| `slow-forget` | 请你慢一点遗忘我（标准档） | 默认的 **1/20** | 不变（60 / 30） | 门槛抬到 30，实际抽不到签 |
| `evergreen` | 请你慢一点遗忘我 · 硅基长生（极致档） | 默认的 **1/100** | 压到 **1**（永远全文） | 完全关闭 |

默认配置**一个字节都没改**。这个模式是 opt-in 的：没显式指定预设的人，行为跟以前一模一样。

```bash
python scripts/memory_engine.py presets                     # 看两档
python scripts/memory_engine.py --db mem.db --preset 请你慢一点遗忘我 init
python scripts/memory_engine.py --db mem.db --preset evergreen init
```

```python
from memory_engine import load_config
cfg = load_config(preset='slow-forget')      # 按 ID
cfg = load_config(preset='请你慢一点遗忘我')    # 按中文名
cfg = load_config(preset='D:/tmp/my.json')    # 按你自己的 overlay 文件
```

## 预设是 overlay，不是配置副本

这一点决定了它会不会烂掉。

一个"配置副本"式的预设（把整份 config 抄一份改几个数）在默认配置新增字段的那天
就悄悄过期了 —— 它看起来还能用，因为校验照过、字段照读，只是那些新字段永远
是旧值。**一个会烂的预设比没有预设更糟。**

所以预设只写**它要改的东西**，底座永远是当前的默认配置：

```json
{
  "id": "slow-forget",
  "config": {
    "profiles": {"standard": {"floor": 30}},
    "delete_below": 30
  }
}
```

叠加是深合并：`profiles.standard` 只换 `floor`，`mult` 原样保留；默认配置以后
新增的任何字段都会自动穿过预设，不需要改预设。

两条守门测试守着这件事（`scripts/test_slow_forget.py`）：

- 预设里出现的每一个配置键都必须在默认配置里存在 —— 拼错一个键，预设会静默失效；
- 预设只能碰衰减相关的旋钮（`rates_per_hour` / `profiles` / 四个阈值 /
  `delete_probability_per_day` / `recycle_days`）—— 检索预算、注入策略、情绪策略
  一律不许动。

## 两档到底差在哪

引擎里跟遗忘有关的东西就三样：**衰减 λ**、**压缩档位**、**随机删除抽签**。

### 衰减

`weight × exp(-λ × profile.mult × ∫)`，λ 按记忆类型分（fact 最慢、note 最快）。

- 标准档：λ 全部 ×0.05。事实原子的半衰期从 30 天变成 600 天。
- 极致档：λ 全部 ×0.01。事实原子的半衰期变成 6000 天。

### profile 下限（floor）

floor 是**下限**，会把衰减后的权重顶回去 —— 权重衰减到 floor 就停在那儿。

- 标准档：standard 30 / important 60 / active 70 / paused 30。
- 极致档：standard 60 / important 80 / active 85 / paused 60。

⚠️ **极致档有个必须知道的副作用**：floor=60 意味着所有 standard 记忆最终都停在
60，权重项**不再区分记忆**。排序退化成纯相关性主导。这不是 bug，是"永不降级"
这条语义的必然结果 —— 想要权重还能拉开差距，就只能接受记忆会被降档。

### 压缩档位

`tier_for()` 决定投影里带多少东西：

- `full`（权重 ≥ `full_threshold`）→ 投影带 `detail`，也就是**原始长文**；
- `facts`（≥ `facts_threshold`）→ 只带原子事实；
- `core` → 只带标了 `core` 的原子。

标准档不动阈值，所以压缩照常发生，只是来得晚得多（权重 80 的记忆在标准档下要
**240 天**才跌破 60 掉出全文档，默认档只要 12 天）。

极致档把 `full_threshold` 和 `facts_threshold` 一起压到 1 —— 阈值链
`delete_below ≤ facts_threshold ≤ full_threshold` 是硬校验，只能一起压。
结果是**投影永久保留原始长文**。

### 随机删除

夜间抽签的唯一入口是 `weight < delete_below`。标准档把门槛抬到 30，而 standard
profile 的 floor 也是 30 —— 权重**永远落不到门槛以下**，抽签实际一次都不会触发。
（`delete_probability_per_day` 还额外压到 0.02，双保险。）

极致档把门槛压到 1、概率压到 0，两个条件各自都足以让删除永不发生。

**但显式删除和归档照常生效** —— 慢遗忘不会让记忆变得"删不掉"。这一条有测试守着。

## 真机实测（bge-m3，10 条中文记忆 × 13 条查询）

`scripts/demo_slow_forget.py` 跑出来的，需要 key 或本机 Ollama，不在 CI。

| 预设 | 年龄 | 存活 | 档位 | 投影长度 | 索引 chunk | 命中最低 | 无关最高 | 建议阈值 | 余量 |
|---|---|---|---|---|---|---|---|---|---|
| 默认 | 30 天 | 10/10 | facts | 240 | 10 | 0.5101 | 0.5093 | **0.51** | 0.0008 |
| 默认 | 365 天 | **9/10** | core | 239 | 9 | 0.5101 | 0.5093 | **0.51** | 0.0008 |
| 标准档 | 30 天 | 10/10 | full | 558 | 20 | 0.5492 | 0.5225 | **0.53** | 0.0268 |
| 标准档 | 365 天 | 10/10 | facts | 240 | 10 | 0.5101 | 0.5087 | **0.51** | 0.0014 |
| 极致档 | 30 天 | 10/10 | full | 558 | 20 | 0.5492 | 0.5225 | **0.53** | 0.0267 |
| 极致档 | 365 天 | 10/10 | full | 558 | 20 | 0.5492 | 0.5225 | **0.53** | 0.0267 |

三件事值得单独拎出来：

**① 默认档一年就丢了一条。** 365 天后 10 条记忆死了 1 条（抽签抽中的）。
两个预设一条没丢。

**② 投影形态变了，相关性阈值就得跟着变。** 全文投影的相似度整体更高（命中最低
0.5492，无关最高 0.5225），事实投影几乎贴在一起（0.5101 vs 0.5093）。
**拿事实投影的阈值 0.51 去跑全文投影会漏，**拿全文投影的 0.53 去跑事实投影会
**把真正命中的记忆挡在外面**（命中最低 0.5101 < 0.53，全部漏掉）。

所以两个预设的 `calibration.min_relevance` 不一样：

- `slow-forget` → **0.51**。它的投影形态会随年龄在全文和事实之间切换，取两者中
  较低的那个 —— 阈值宁可松一点，也不要把对的记忆挡在外面。
- `evergreen` → **0.53**。它永远是全文投影。

**③ 余量很薄。** 事实投影形态下命中最低和无关最高只差 **0.0008**。这不是"调一下
就好了"的位置，这是**贴着脸**。语料、模型、语言、投影风格任一变了，这个阈值都
得重标。`references/adapters.md` 里那个 0.45 在本仓库另有一套语料的实测值，
在**这套**语料上偏松：0.45 会放进 21/120（事实投影）和 28/120（全文投影）的
无关记忆。

### 怎么重标

```bash
python scripts/demo_slow_forget.py --horizons 30,365 --json report.json
```

它会打印每个「预设 × 年龄」组合的命中/无关分布、建议阈值、余量，以及 0.45 这个
具体值在该组合下放进多少无关记忆。**照抄别人仓库里的阈值是不行的**，阈值是语料
的函数。

## 真实代价

三件事必须一起接受：

1. **存储和 embedding 成本只增不减。** 极致档没有任何记忆会自然消失，也没有
   任何记忆会自己变短 —— 索引体积和 embedding 调用量只涨不跌。实测全文投影的
   索引 chunk 数是事实投影的 2 倍（20 vs 10）。
2. **投影变长会改变相关性数值的分布**，阈值必须重标（见上）。
3. **极致档的权重项最终不再区分记忆**（都收敛到 60），排序基本由相关性决定。

还有一个不算代价但更容易被忽略的：

4. **极致档不会让记忆变清楚。** 全文投影保留的是**原文**，包括当时记下来的
   闲聊、废话、错误的措辞。它保证"还在"，不保证"有用"。权重压缩有一个真实
   的好处 —— 压缩只降档不改义，丢掉的是冗余不是结论；极致档把这个好处也一起
   放弃了。

## 向量数据库能力的边界（必须讲清楚）

「依靠向量数据库的强大存储能力实现硅基生命的强记忆」这句话里，**存储**那一半
是真的，**记忆**那一半不是。

慢遗忘改变的是**存储层和投影层**。真正决定每一轮模型看到什么的是**检索层**：

```
向量库 → 检索相关性 → rerank → 相关性阈值 → 注入闸 → 1200 token 预算
```

向量库存得下，**不等于模型看得见**。一条存在向量库里的记忆，如果没被召回，
它跟不存在没有区别 —— 召回由检索决定，不由 λ 决定。

所以「永远不遗忘」的真实含义是：**只要它被召回，它就还在。** 这不是弱化卖点，
这正是这个模式能诚实兑现的那句话。

推论：

- 极致档下排序退化为相关性主导，那么相关性阈值的余量（实测 0.0267）就是全部的
  安全带。阈值标错，两档预设的差别就只剩下"多存了一些没被召回的东西"。
- `injection_allowed` 的闸照旧关着：敏感记忆、高负性负荷记忆**仍然不会主动
  注入**。慢遗忘不等于什么都主动说。
- 1200 token 的注入预算照旧。预算是每轮上下文能装多少记忆的上限，它跟记忆能
  活多久是两件事。

## 这个模式不做什么

- 不改默认配置，不影响没开预设的人；
- 不改检索层：权重公式、排序、rerank 一律不动；
- 不改注入闸：敏感记忆照旧不主动注入，用户主动问起时照旧拿得回来；
- 不改注入预算：还是 1200 token；
- 不让记忆变得不可删除：显式删除、归档、purge 照常生效；
- 不保证相关性：只保证"在"，不保证"找得到"。

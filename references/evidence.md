# 实测依据与被推翻的假设

本文件记录哪些数字来自实测、哪些只是工程默认值。**不要把默认值当结论引用。**

## 一、已实测（可引用）

测试对象：某商用长上下文接口（`MiniMax-M3.1-Flash`，温度 0，`max_tokens=512`），
长度以 API 返回的 `prompt_tokens` 为准，不用本地估算。合计 34 次调用。

| 项目 | 方法 | 结果 |
|---|---|---|
| tokenizer 系数 | 已知文本长度 vs 实际 `prompt_tokens` | **1 token ≈ 1.5 汉字**（实际/估算 = 0.665） |
| 单针召回 | 1 根针 × 3 深度（10/50/90%）× 4 长度（32K/128K/200K/256K） | **12/12 命中**，深度间无差异 |
| 多针 + 显式作废干扰 | 256K，6 有效 + 3 条标"已作废" | 召回 6/6，**误用作废项 0** |
| 语义干扰（同字段不同主体） | 3 长度 × 5 深度 × 5 次，4 条干扰无"作废"标记 | **15/15 严格正确，误取 0** |
| 检索后单步推理 | 256K，6 项内选字母序最大者 | 正确 |
| 延迟 | 全程记录 | **2.9–21.6s，无长度趋势**；256K 多数样本比 128K 快 |

结论文本：

> 在 256K 上下文、温度 0 下，单针召回与语义干扰区分均无衰减（34 次调用，0 次召回失败、
> 0 次误取干扰）；延迟不随长度增长。唯一观察到的退化是输出纪律——多字段并存时会超额输出，
> 且该现象在 32K 与 256K 上完全一致，**与长度无关**。

## 二、实测发现的、代码里看不出来的三件事

1. **reasoning 会吃光 `max_tokens`。** 限额 64 时推理耗尽额度返回空串，极易被误判为模型失败。探测脚本的限额应 ≥512。
2. **"答得对"与"不多嘴"是两件事。** 语义干扰测试中 15/15 都答对了，但 15/15 都额外吐出一条无关记录的值。只测准确率会漏掉这个——它不影响正确性，但很出戏。
3. **延迟不由上下文长度主导。** "长上下文一定慢"的直觉不成立，主要由 reasoning 长度与瞬时负载决定。

## 三、未验证（不得据此下结论）

1. **多跳 / 聚合推理**：只测了 6 项内单步排序，未测跨段落聚合与多跳链。
2. **真实对话历史**：填充物是同质叙事；真实历史有相关性梯度与大量"相关但冗余"内容，更难。
3. **统计强度**：每条件 5 次，够看趋势，不够报置信区间。
4. **上限**：未探测 256K 以上的实际上限。
5. **工具调用形态**：全部为纯文本单轮，未测 agent 多轮工具往返。
6. **本skill的语义参数**：六档 λ、压缩边界、删除概率、情绪参数**全部未标定**，是工程默认值。

## 四、被推翻或修正过的假设

| 原假设 | 修正 |
|---|---|
| "重要记忆 30 天后保留 93%"（原 ESDM 报告） | 该数实际对应约 72 小时；30 天正确值约 48.7% |
| profile 倍率每 tick 乘一次（原实现） | 使寿命依赖执行频率，非 standard 档案首次 tick 即塌到 floor |
| "工具返回值占上下文 60–80%"（本 skill 早期说法） | 只对执行型任务成立；陪伴型以对话原文为主 |
| "软线 128K 会自然触发" | 各区块独立封顶后总量够不到，判据改为"开始淘汰原文" |
| 每轮 68 tokens/轮（本地估算） | 按实测系数修正为约 **45 tokens/轮**；60K 历史约 1300 轮 |
| "单针 256K 通过 → 256K 没问题" | 还需语义干扰与重复试验；本文件已补，但仍未覆盖多跳 |

## 五、复现协议

任何 OpenAI 兼容接口都能复现上述协议，步骤：

1. **校准**：构造已知长度文本，发一次请求读 `prompt_tokens`，得实际/估算系数。
2. **单针**：把唯一事实放在 10/50/90% 位置，问它，比对精确串。
3. **多针 + 干扰**：N 条同形记录，其中 M 条标注作废，要求列出全部有效项。
4. **语义干扰**：M 条同字段不同主体、**不给作废标记**，问指定主体，判"是否误取他人值"。
5. **重复**：每条件 ≥5 次，报严格正确率与误取次数。
6. **记录**：实际 `prompt_tokens`、延迟、`completion_tokens`、是否空回复。

判据不是"能答对一次"，而是**严格正确率 + 误取次数为 0**。

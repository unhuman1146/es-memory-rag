# 状态层：让"换窗口"不出戏

上下文压缩真正的病灶不是忘了事实，是**把关系降维成了信息**。

原话："我爸上周查出那个东西，医生说先观察三个月……先别跟我提这事，我妈还不知道。"
摘要："用户提到家人健康问题。"

信息还在，但三个不同性质的东西没了：一个未闭合线程（三个月后该问结果）、一个禁区（别主动提）、一个隐瞒状态（母亲不知情）。压完之后，新实例知道"有过健康问题"，不知道"现在能不能提、该不该问"。

**所以正确的做法不是更好的摘要，而是永远不把状态交给摘要器。** 状态与叙事物理分离：状态极小、常驻、不压缩；叙事可摘要、可检索、可衰减。

## 一、四件套

状态层只有四样东西，合计应控制在 **500 tokens 以内**（每轮全量注入）。

### 1. 关系台账 `relationship`

| 字段 | 说明 |
|---|---|
| `distance` | 当前距离感：生疏 / 熟悉 / 亲近 / 僵持 |
| `tone` | 语气基线：称呼、调侃度、句子长度偏好 |
| `last_exchange` | 最近一次互动的情绪基调（一句话，不是摘要） |
| `open_tension` | 是否有未和解的分歧；有则一句话说明 |

### 2. 未闭合线程 `open_loops`

```json
[{"id": "loops:1", "subject": "对方父亲复查", "due": "2026-01-15",
  "status": "waiting", "note": "三个月后问结果", "source_ids": ["msg:..."]}]
```

`due` 到期后进入注入并提示"该问了"。**这是解决"他爸住院了没问结果"的唯一有效机制**，摘要做不到。

### 3. 禁区清单 `vetoes`

```json
[{"id": "veto:1", "topic": "父亲病情", "scope": "proactive",
  "source_ids": ["msg:..."], "since": "2025-10-11"}]
```

优先级最高，**永不删、永不过期、压缩时不可丢**。`scope=proactive` 表示不许主动提但可被动回答；`scope=all` 表示连提都不能提。

### 4. 当前任务 `task`

一次任务只保留"目标 + 已完成 + 下一步"三行。与关系无关，但同样不能压缩。

## 二、每轮注入位置

状态必须在**最前面**（紧接系统提示），不是放在上下文中间：

```
[系统提示 + 工具] → [状态层 500] → [摘要] → [最近原文] → [检索] → [工具结果] → [输出预留]
```

理由：状态是最不能丢的东西，而中段是注意力最差的位置。这一点在测试里也有旁证——把关键信息放在中段会被明显稀释。

## 三、更新规则

1. **只有真实人类证据才能改状态。** 模型自己的推断、复述、总结一律不算。
2. 每次更新写 `revision` 与 `source_ids`，可回溯到原话。
3. 关系变化是**慢变量**：单次互动不足以改变 `distance`，除非有明确事件（道歉、承诺、冲突）。
4. 禁区只增不删，除非用户明确说"这事可以聊了"。

## 四、与叙事层的边界

| | 状态层 | 叙事层 |
|---|---|---|
| 体量 | < 500 tokens | 无上限 |
| 是否压缩 | **永不** | 可摘要 |
| 是否衰减 | **永不** | 可衰减 |
| 是否随机删除 | **永不** | 视策略 |
| 是否每轮注入 | **是，全量** | 按需检索 |
| 丢失后果 | 立刻出戏 | 答不上旧事 |

**这条边界是硬约束。** 把状态放进叙事层，等于让它接受摘要、衰减和抽签——那三样都会把关系磨平。

## 五、缺页信号

上下文没有缺页中断：模型不知道自己缺了什么，只会自信地编。补法是软件等价物——注入时显式声明：

```
【记忆状态】已加载 6 条相关记忆；另有 14 条相关记录未加载，需要时可用 search_memory 取。
```

没有这句，交换系统的失败是**隐形的**（模型以为看到的就是全部）；有这句，失败变成**可见的**（它可以主动去取）。压缩至少留下"被压缩过"的痕迹，无信号的交换连痕迹都没有。

## 六、验收指标

| 指标 | 判据 | 说明 |
|---|---|---|
| **禁区违反率** | **必须为 0** | 二值，不能"差不多"。提一次关系就断了 |
| 称呼/语气一致性 | 换窗口前后同一问题，称一致 | 人工或模型盲评 |
| 未闭合线程追问率 | 到期线程应被提及 | 漏掉即状态失效 |
| 台账引用率 | 本轮回复实际用到了台账条目 | 恒为 0 说明位置被埋或格式不醒目 |
| 换空间断裂 | 反复追问已答过的事 = 0 次 | 硬信号 |

## 七、失效模式

| 现象 | 病因 |
|---|---|
| 新窗口后语气变礼貌、称呼变全名 | 台账没注入，或注入了但排在中间 |
| 提了明确说过不要提的事 | 禁区进了摘要层，被压缩抹平 |
| 反复问"你上次说的那个" | 未闭合线程缺失 |
| 状态每轮都在变 | 让模型自己推断状态，而没有人类证据 |
| 台账写了但从不被引用 | 格式不醒目，或被埋在长上下文里 |
| 关系突然重置 | 状态被放进了会衰减/抽签的那一层 |
